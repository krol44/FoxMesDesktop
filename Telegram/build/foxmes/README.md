# FoxMes Desktop release scripts

These scripts are the only supported path for FoxMes release artifacts. They build `Release`, require Qt WebSockets, disable the upstream auto-updater and crash upload, and compile with `FOXMES_ALLOW_ENDPOINT_OVERRIDE=OFF`.

The Windows, macOS and Linux scripts produce the platform artifacts in `artifacts/`. `make-release-manifest.py` combines them with `version.json` and `SHA256SUMS`. `verify-source.py` audits user-facing package metadata before a build.

## Windows desktop shortcuts during updates

Silent installation (`/SILENT`, `/VERYSILENT`), including automatic updates started by an existing client, skips desktop shortcut creation. Existing shortcuts are preserved, and shortcuts deleted by the user are not recreated. The normal installation wizard still offers the desktop shortcut checkbox.

Windows CI tests silent installation with the `desktopicon` task explicitly selected, an update with an existing shortcut, and an update after that shortcut is deleted. These checks run after the installer is built and do not compile the app again.

## Caches and when to warm them

A GitHub job runs for at most six hours, and a cold build (dependencies, then the app) may not fit. The dependency caches are keyed on `prepare.py` and `qt_version.py`, so they go cold after an upstream merge that touches either; the macOS ones also go cold when the runner image updates Xcode, because `prepare.py` keys every stage on the compiler and SDK. Linux builds its `centos_env` image whenever `centos_env/` changes, about two hours.

Each platform runs as three sequential jobs: `windows-deps` → `windows-build` → `windows`, `macos-deps` → `macos-build` → `macos`, and `linux-deps` → `linux-build` → `linux`. Each job has its own six-hour limit. Dependency preparation no longer uses the compilation job's time budget. The compile step gets the remainder of 330 minutes from the start of its job, leaving time to save the compiler cache and transfer the compiled app.

Windows and macOS dependencies are transferred to the next job as artifact archives. The Windows archive stores the contents of symbolic and hard links as regular files, so Git Bash can extract Rust tool proxies without creating links. The archive is checked for link entries before upload. The compilation job selects the same installed MSVC or Xcode version used to prepare the dependencies. It checks the dependency key before configuration; the macOS key includes the Xcode and SDK versions. If the required version is no longer installed on an updated runner, or the key differs, the job prepares the dependencies again and caches them for the selected toolchain. In this case, dependency preparation counts toward the compilation job's time budget. Linux passes the GHCR digest of the prepared `centos_env` image and requires that exact image: a publication or pull failure does not rebuild dependencies inside the compilation job. The compiled `FoxMes.exe`, `FoxMes.app`, and installed `FoxMes.AppDir` are transferred to packaging as archives, preserving executable permissions and symbolic links. Intermediate artifacts are retained for seven days and are excluded from the published release.

The packaging jobs do not compile the app again. The scripts provide `build-windows.ps1 -PackageOnly`, `build-macos.sh package`, and `build-linux.sh package` for this purpose. Windows compilation uses `-OnlyCache -SkipDeps`, while dependency preparation uses `-DepsOnly`. Linux packaging can be retried against the same `FoxMes.AppDir`, including after a tool download fails. The existing commands for complete local builds keep their previous behavior.

Windows and macOS dependency caches, the Linux image in GHCR, and compiler caches for all three platforms are preserved. Compiler caches are saved after a successful compile and after a compile step fails or times out. Retrying a failed compilation job uses that cache together with the prepared dependencies from the preceding stage; retrying a packaging job uses the compiled app. The `only_cache` mode runs dependency preparation and compilation without signing or packaging.

macOS CI builds only the `Telegram` target with two parallel tasks. A supervisor prints CPU, memory and swap diagnostics every minute and stops its compilation process group two minutes before the outer step timeout. After compilation, the working compiler cache is copied to a separate snapshot for upload, so archive creation does not read a cache that build processes can still change. Cache statistics are printed after successful, failed and timed-out builds. `FOXMES_BUILD_JOBS` can override the parallel task count; outside CI it defaults to the CPU count.

A cache saved by a tag run is visible to that tag alone. After a tag run, `refresh-caches` starts a `workflow_dispatch` run on `master` with `only_cache`, so future releases can use compiler caches from the default branch. `cleanup-caches` deletes the caches of a successful tag run and keeps only the newest compiler cache for each platform on `master`. This does not change GitHub's cache retention settings: by default, caches are deleted after seven days without access, so a release after a long break may need a cache warm-up first.

ccache enters the macOS build through the Xcode `CC` setting, since the Xcode generator ignores `CMAKE_<LANG>_COMPILER_LAUNCHER`, and every C-family compile gets `-Xclang -fno-pch-timestamp`, without which ccache will not cache anything that uses a precompiled header. ccache cannot cache MSVC compiles that use a precompiled header, and the sources rely on what that header includes, so whenever the Windows build uses ccache, `force-include-pch.cmake` (passed as `CMAKE_PROJECT_INCLUDE`) replaces each precompiled header with a `/FI` of the same header. The `centos_env` image sets `CCACHE_DISABLE` for its own stages, so `build-linux.sh` removes it for the app.

After a dependency change, run `workflow_dispatch` on `master` with `only_cache` checked before pushing the tag, so that the slow part happens outside the release.

Its type-2 runtime is pinned to release `20251108` (commit `dd6cebedcbddde9c82f89b011e8e1d40b6e43868`) with SHA256 `2fca8b443c92510f1483a883f60061ad09b46b978b2631c807cd873a47ec260d`. Both URLs use immutable release tags; the release job never downloads a mutable `latest` or `continuous` asset.

Version 1.13.2 is unsigned. The macOS app is the exception: it carries FoxMes's self-signed certificate (`codesign.pem`, key in the `macos-signing` environment) so that macOS keeps its privacy permissions across updates, but it is not notarized. Windows SmartScreen and macOS Gatekeeper may warn on first launch. Users should verify `SHA256SUMS` and the GitHub build provenance before running an artifact. No Microsoft Store, Mac App Store, Snap, Flatpak or WinGet package is produced.
